What it does

Not autocomplete. A teammate with a shell.

Claude Code works the way you do: it explores, makes a change, runs the program, reads what broke and tries again. Four things it does all day.

HOOKS

Rules that always run.

Shell commands that fire on lifecycle events. Format after every edit, block a dangerous command, ping your team when a task ends. Deterministic, not a polite suggestion.

PreToolUse→ Edit(src/api.ts)→ PostToolUse→ prettier --write
"hooks": { "PostToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "npx prettier --write ." }] }]}

It remembers how you work.

Drop a markdown file in your repo. Conventions, commands and gotchas load into every session.

A real workflow

From issue to pull request, while you get coffee.

STEP 1

Read the issue

Point it at the ticket. It pulls the description and linked context through MCP.

STEP 2

Plan the change

In plan mode it explores read-only and proposes an approach for you to approve.

STEP 3

Edit the files

Changes land across the codebase, with a checkpoint at every step.

STEP 4

Run the checks

Tests, types and lint run for real. It iterates until the output is clean.

STEP 5

Open the PR

A branch, a commit and a pull request with a description a human can review.
